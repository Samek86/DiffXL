## 1. 目的と成功の定義

### 1.1 目的

1. MiniMap を **ユーザーが画面を見ながら操作するのと同じ経路**で検証する（API だけの成功にしない）。
2. 差分マーカー・シート帯・ビューポート帯・クリックジャンプ・スクロール追従が一体として正しいことを示す。
3. 不具合があれば再現手順と画面証拠で切り分ける。

### 1.2 「完璧」の判定基準（Definition of Done）

| # | 観点 | 合格条件 |
|---|------|----------|
| D1 | レイアウト | シート帯が **SheetPairs 順**で縦に並ぶ。帯ラベルが読める。 |
| D2 | マーカー | 差分 69 件相当の黄マーカーが各シート帯内の **行位置に対応**して表示される。 |
| D3 | ビューポート | 青帯＋ラベル（`シート略 · 行N`）が **現在の Excel ScrollRow** に一致する。 |
| D4 | クリックジャンプ | マーカーまたは帯クリックで **左右シート切替＋行ジャンプ**。ステータスに `MiniMap → シート!行…`。 |
| D5 | 精度 | ジャンプ後 `ScrollRow` が目標行 ±3 以内（左右とも）。 |
| D6 | シート横断 | 表紙 / 売上サマリ / 製品カタログ / 長い一覧など **複数シート**で D4–D5 が成立。 |
| D7 | スクロール追従 | Excel 縦スクロール後、MiniMap 青帯が **クリック無しで**追従する。 |
| D8 | 強調連動 | 差分強調 OFF で黄マーカー消失、ON で再表示。 |
| D9 | 安定性 | 連打・ドラッグ・シート切替後も StackOverflow / 未処理例外なし。 |
| D10 | 証拠 | 各ケースで **操作前・操作後スクリーンショット** とログ抜粋を残す。 |

既存 `--auto-live-test` の `MINIMAP_OK` / `MINIMAP_MULTI_OK` は **必要条件**だが **十分条件ではない**。  
本計画では **画面を見て確認**した証拠を必須とする。

## 2. テスト環境

| 項目 | 値 |
|------|-----|
| OS | Windows 10/11 x64 |
| Excel | インストール済み（COM 埋め込み） |
| 実行ファイル | `C:\JUN\WORK\DiffXL\40_リリース\DiffXL.exe` |
| 主操作 | **Paseo computer-use**（デスクトップ画面のキャプチャ・クリック・スクロール等） |
| 補助操作 | PowerShell UI Automation + `CopyFromScreen` + エージェントによる画像読取 |
| 使用しないもの | Orca アプリ / `orca` CLI / `stablyai/orca` 由来の computer-use スキル |
| エビデンス先 | `10_管理資料/テスト/エビデンス_minimap_YYYYMMDD_HHMMSS/` |

### 2.1 操作原則（画面認識ループ）

```
1. 画面キャプチャ（ウィンドウ全体 or MiniMap 拡大）
2. 画像を読んで状態を認識（シート帯・黄点・青帯・ステータス文字列）
3. 認識結果に基づきクリック / ホイール / ドラッグ
4. 再キャプチャして期待状態と比較
5. PASS/FAIL とスクリーンショットを記録
```

API 直呼び（`OnMiniMapNavigate` のみ）は **補助**とし、主系列は **マウスクリック経路**とする。

### 2.2 ツール優先順位

| 優先 | 手段 | 用途 |
|------|------|------|
| 1 | **Paseo computer-use** | 画面認識・クリック・スクロール・ドラッグの主経路 |
| 2 | UI Automation + 画面キャプチャ | ファイル選択ダイアログ、Paseo が弱い操作の補完 |
| 3 | `--auto-live-test` | COM 精度の機械検証（画面操作の代替にしない） |

ウィンドウ選択時は **プロセス名 `DiffXL` または PID** を明示する。  
タイトルに「DiffXL」を含む Visual Studio など他アプリと取り違えないこと。

## 5. 自動試験との役割分担

| 経路 | 役割 |
|------|------|
| `--auto-live-test` | COM 精度・複数シート・設定保存の回帰（CI 的） |
| 本計画の画面操作（Paseo computer-use 等） | UX 正しさ・描画・実クリック経路・視覚証拠 |
| 両方 PASS | MiniMap 完全動作のリリース判定 |

auto-live のみ PASS で本計画 FAIL の場合は **リリース不可**（見た目／クリック経路の欠陥）。

## 6. 実施手順（セッション手順書）

1. **エビデンスフォルダ作成**  
   `10_管理資料/テスト/エビデンス_minimap_YYYYMMDD_HHMMSS/`
2. **比較状態まで到達**（対話 or 既存ハーネス）
3. **フェーズ A** 静的キャプチャ
4. **フェーズ B** クリック系列（画面認識しながら）
5. **フェーズ C** スクロール追従
6. **フェーズ D** 強調・再比較・リサイズ
7. **フェーズ E** 境界
8. **auto-live 再実行**で COM 精度を再確認
9. `test-results-minimap.md` に合否集計

### 6.1 Paseo computer-use 利用時（主経路）

1. Paseo が稼働していることを確認する（daemon / エージェント環境）。
2. DiffXL ウィンドウを **プロセス名または PID** で特定する（他アプリと取り違えない）。
3. 画面キャプチャ → 画像・UI 状態を読み取り → クリック / スクロール / ドラッグ。
4. 操作ごとにキャプチャをエビデンスへ保存する。
5. ステータス文言（`MiniMap → …`）とシート帯ラベルを before/after で照合する。

具体的なツール名・パラメータは、利用中の Paseo / エージェントに付属する computer-use 手順に従う。  
**`orca` コマンドや Orca アプリは起動・参照しない。**

### 6.2 補助経路（Paseo computer-use が使えない場合）

- PowerShell UI Automation + `CopyFromScreen` で操作とキャプチャ
- キャプチャ PNG をエージェントが画像として読み認識
- 座標クリックはウィンドウ矩形＋MiniMap 右端列から算出
- 実施結果に「補助経路で実施」と明記する（BLOCKED にしない。ただし主経路未実施である旨を残す）

## 9. 既知の注意点（実装知識）

コード上の仕様（`MiniMapControl` / `OnMiniMapNavigate`）:

- クリックは **シート切替 → 行 Goto** の順。シート切替欠落は「無反応」に見える。
- 行は Address → OrderHint 下位 → ratio 推定の優先。
- ビューポート帯は `SetViewport(sheet, scrollRow)` で本文 ScrollRow と同期。
- マーカー色は差分強調トグルと連動。

テストで FAIL した場合の切り分け順:

1. ステータス文言が出るか（イベント到達）
2. シート UI が変わったか
3. ScrollRow が目標近傍か
4. MiniMap 青帯が追従したか
5. ログに例外がないか
