## 0. 한 문장으로 고정하는 제품

> DiffXL은 Excel 화면을 재현하지 않는다.  
> **같은 내용이 같은 개수만큼 있으면 같다.** 표는 테두리（또는 Excel 표）로 잡은 뒤 행 단위로 맞춘다.  
> 이미지는 **나타난 순서**와 겉보기로 맞춘다. 수식·매크로·피벗·차트는 보지 않는다.

이 문장과 다른 기능은 넣지 않는다. README·시작 화면·상태줄이 이 문장을 사용자에게 말한다.

내용 베이스（위치 무시）를 폐기하지 않는다. 폐기는 “엑셀 주소 비교기로 회귀”이고, 이미 버린 길이다.  
고치는 것은 **엔진과 화면이 다른 답을 내는 것**, **임계값이 거짓 짝을 만드는 것**, **문서가 이전 앱을 가리키는 것**이다.

## 1. 비판에서 남기는 것 / 버리는 것

### 지금 한다（의미 있음）

| ID | 문제 | 왜 지금인가 |
|----|------|-------------|
| T1 | 엔진 차분 목록 ≠ 스트림 짝 | 제품이 두 입을 가짐. MiniMap·하이라이트가 거짓말 |
| T2 | 수동 시트 짝 1개가 동명 자동 매칭을 끔 | 실사용에서 시트 전체가 비교에서 빠짐 |

| T4 | 표 검출이 테두리만, 검출 전환이 설명되지 않음 | 테두리 유무로 대수 전체가 바뀜 |

### 나중에（의미는 있으나 지금 범위 밖）

- `.xlsm` ZIP 읽기（매크로 무시）
- 수식 vs 값 토글
- 셀 “이동” 검출
- 이미지 순서 무시（Hungarian 부활）
- 한국어 UI
- MainWindow MVVM 전면 분해
- 탭 UI 복원（스트림을 유지하는 쪽이 맞음. 종류 필터만）

- Excel COM / 1px 재현
- `.xls`（복합 포맷, 이득 대비 비용 큼）
- 글꼴·행고·열너비 비교
- 설정 화면의 모든 YAML 노브를 UI화（비교 임계값만 페이즈 2）
- 증거 PNG 폴더를 품질 게이트로 유지

## 2. 페이즈와 종료 조건

한 페이즈가 끝나기 전에 다음 페이즈의 “예쁜 기능”을 넣지 않는다.

```
H0 정직함     →  H1 한 개의 진실   →  H2 표가 거짓말을 줄임
                                          ↓
H4 배포 가능  ←  H3 찾아지는 UX
```

### H0 — 정직함（문서·유령 삭제, 수일）

**목표:** 앱이 무엇을 하는지 거짓말하지 않는다. 코드는 최소.

할 일:

1. README / 시작 화면 / 비교 완료 상태줄에 §0 한 문장을 넣는다.
2. 요건 V-01d를 **스트림 + 종류 필터**로 고친다. 탭은 폐기했다고 명시.
3. N-04는 “미구현 → H3”로 상태를 적는다. 있는 척하지 않는다.
4. `テストケース一覧` / `06_リリース配布_検証` / `_smoke/README`에서 Excel 임베드·앵커 다이얼로그·좌우 Excel 표시를 삭제하거나 “역사”로 옮긴다.
5. 컴파일되는 COM 유령을 끊는다: `SmokeGoto` / `SmokeEmbedGoto` / `DualEmbed`가 없는 타입을 참조하면 제거 또는 `#if` 폐기. `BtnImageLink` 핸들러·미사용 `DiffOverlayLayer` 정리.
6. `LICENSE` 추가（앱 본문 + OSS 안내）. README “정비 중” 삭제.
7. “단일 exe”는 Release 폴더에 DLL이 없으면 유지, 있으면 **문구를 현실에 맞춘다**（Costura + native AppData. 옆 DLL이 있으면 주장하지 않음）.

종료 조건:

- 신규 사용자가 README만 읽고 `.xlsm` / 수식 / 주소 비교를 기대하지 않는다.
- `grep`으로 `ExcelWorkbookSession` / “左右 Excel 表示”가 **현행 게이트 문서**에 없다.
- 솔루션이 죽은 임베드 스모크 없이 빌드된다.

### H1 — 한 개의 진실（비교의 핵심, 1–2주）

**목표:** 리스트·본문·MiniMap이 같은 짝을 가리킨다.

원칙:

- **정렬의 정본은 하나.** `ContentStreamBuilder`가 만든 pair 인덱스가 MiniMap 마커·하이라이트·차분 목록의 키다.
- `DiffEngine` 아이템은 pair에 **붙는 주석**이지, 다른 정렬이 아니다.
- 스트림이 “Match”인데 리스트가 “왼쪽만+오른쪽만”이면 버그로 취급한다.

할 일:

1. pair마다 `StreamPairId`（또는 기존 index）를 `DiffItem`에 심는다.
2. 스트림 강제 Match（예: 검증 노트 B17/B19）는 **같은 규칙으로 DiffItem을 만들거나**, 리스트에도 “대응됨·내용 다름” 한 줄로 낸다. 스모크가 모순을 고정하지 못하게 고친다.
3. `SheetMatcher`: 수동 짝은 **그 시트만** 덮어쓴다. 나머지 동명 시트는 자동 매칭을 유지한다.
4. 이미지/표 Skip은 스트림과 엔진이 같은 Skip을 쓴다.
5. 회귀: `ContentDiffSmoke` + `ContentStreamSmoke`에  
   “스트림 Match ⇒ 리스트가 서로 무관한 편측 Text 두 줄이 아님”을 넣는다.

종료 조건:

- `content_diff` / `full_feature` / `stress_suite`에서 본문 클릭 ↔ 리스트 ↔ MiniMap이 같은 pair.
- 수동으로 표지만 짝지어도 `매출`/`매출`은 계속 비교된다.

### H2 — 표가 거짓말을 줄임（1–2주）

**목표:** 표 경계와 행 짝이 “우연히 같아 보이는 다른 행”을 덜 만든다.

할 일:

1. **검출:** `xl/tables`（Excel 표）가 있으면 그걸 우선한다. 없을 때만 테두리 flood. 검출 출처를 pair 메타에 남긴다.
2. **전환 가시화:** 이 블록이 표로 잡힌 이유를 툴팁/헤더에 한 줄（`Excel 표` / `테두리 영역` / `느슨한 셀`）.
3. **열 길이:** `min(cols)`로 자르지 않는다. 여분 열은 `TableCellChange` 또는 “열 수 차이” 한 건.
4. **행 유사도:** 2열 행에서 1칸만 같으면 Match 금지. 빈 칸을 일치로 세지 않는다. 임계 0.5는 열이 많을 때만.
5. **표 안 배경:** 비교하지 않는다면 UI/README에 명시. 비교한다면 zebra 예외만 둔다. 지금처럼 조용히 drop하지 않는다.
6. 스모크: 여분 열, 2열 충돌, `xl/tables` 우선, 테두리 없는 목록은 loose로 남는 것.

종료 조건:

- `12345` vs `1245`는 유지.
- 이름만 같은 다른 ID 행이 오매칭되지 않는다.
- 오른쪽만 있는 열이 사라지지 않는다.

이미지 0.15 임계는 이 페이즈에서 **숫자만 올리지 않는다.**  
대신 스트림이 이미 쓰는 0.55와 **한 숫자로 맞추고**, 미달이면 Skip이지 Image Match가 아니다（H1과 함께）.

### H3 — 찾아지는 UX（약 1주）

**목표:** 차분을 찾기 위해 MiniMap을 문지르지 않아도 된다.

할 일:

1. **N-04:** `F8` / `Shift+F8`（또는 `F3`/`Shift+F3`）으로 현재 시트 차분 pair 이동. 툴바 이전/다음. MiniMap 노란 마커 클릭 = 그 pair로 점프（히트 복구）.
2. **시트 선택 한 줄:** 툴바 페어 콤보가 정본. 좌우 콤보는 페어를 바꾸거나, 독립이라면 라벨을 “이 칸만 보기”로 바꾼다. 둘 다 “시트”라고 쓰지 않는다.
3. **툴바:** 죽은 이미지 대응 삭제. “이 조합으로 비교”는 이명 시트일 때만 강조.
4. **종류 필터:** 스트림 상단 칩 `전부 / 표 / 이미지 / 셀`. 탭 복원이 아님.
5. MiniMap 제목을 `差分マップ` 등 UI 언어에 맞춘다.

종료 조건:

- 키보드만으로 시트 안 차분을 순회.
- 마커 클릭이 스크럽을 빼앗지 않으면서 pair로 이동（클릭=점프, 드래그=스크럽）.

### H4 — 배포 가능（수일–1주）

**목표:** 베타라도 “받아도 되는 빌드”가 있다.

할 일:

1. `ContentDiffSmoke` / `ContentStreamSmoke` / `MiniMapViewportBandSmoke` / `ImageOverlayAlignSmoke`를 **한 스크립트**로 빌드 후 실행. GitHub Actions windows-latest에서 돌린다（Excel 불필요）.
2. AutoLive를 `MainWindow`에서 분리（별 어셈블리 또는 `COMMON/AutoLiveTest`만 참조）. 프로덕션 창에 1400행 QA가 남지 않게.
3. `VERSION` / Assembly / CHANGELOG Unreleased를 한 베타로 묶는다（예: `0.2.0-beta.1`）. H0–H3가 들어갔을 때.
4. Release\|x64 산출물을 열어 DLL 옆 여부를 확인하고 README와 일치시킨다.
5. `_smoke` exe·ffmpeg 잔여물을 gitignore로 고정.

종료 조건:

- PR/push에 스모크가 돈다.
- 태그 하나에 라이선스 + 정직한 README + 통과한 스모크가 붙는다.

## 4. 권장 일정（한 사람 기준）

| 순서 | 페이즈 | 대략 |
|------|--------|------|
| 1 | H0 정직함 | 2–4일 |
| 2 | H1 한 개의 진실 | 7–12일 |
| 3 | H2 표 | 7–10일 |
| 4 | H3 UX | 5–7일 |
| 5 | H4 배포 | 3–5일 |

합계 **약 5–7주**. H0는 바로 착수 가능. H1이 본론이다. H3를 H1보다 먼저 하면 예쁜 내비게이션이 틀린 pair로 점프한다.

`.xlsm` / 수식 토글 / 이동 검출은 이 5–7주 **다음** 로드맵이다. H4 태그 이후에만 연다.

## 5. 전체 로드맵과의 관계

`10_管理資料/計画/00_全体ロードマップ.md` 페이즈 G（내용 베이스·COM 폐지）는 **구현은 되었으나 문서·의미가 닫히지 않았다.**

본 문서는 **페이즈 H**다.

- G의 완료 조건에 “요건이 내용 비교와 모순 없음”이 있다 → H0가 그걸 닫는다.
- G가 남긴 이중 정렬 → H1이 닫는다.

기존 08 내용동기 UX는 H3에 흡수한다. 새 UX 기능을 08에 더 쌓지 않는다.
